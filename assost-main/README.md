# ASOST Dashboard — التشغيل

هذا الحزمة تربط الفرونت إند (الداشبورد) بالباك إند (`PF.py`) مباشرة، بحيث كل
التحكم والمراقبة يحصل من الواجهة. **لم يُعدَّل أي سطر داخل `PF.py`** ولا أي
منطق ترجمة، ولا نظام مفاتيح الـ API (بقي يدوياً بالكامل داخل الكود الأصلي
تماماً كما طلبت).

## المحتويات

```
PF.py              ← محرك الترجمة الأصلي (بدون أي تعديل)
server.py          ← طبقة الربط الجديدة (تستدعي PF.py وتُخرج REST API + تصدير الواجهة)
requirements.txt   ← كل المتطلبات (لمحرك PF.py وللسيرفر معاً)
static/            ← الفرونت إند (index.html / style.css / script.js + الصور)
README.md          ← هذا الملف
```

## 1) التثبيت

يحتاج Python 3.10 أو أحدث.

```bash
python3 -m venv venv
source venv/bin/activate        # على ويندوز: venv\Scripts\activate
pip install -r requirements.txt
```

> `PyMuPDF` و `tiktoken` ضمن requirements.txt لأنهما يحسّنان جودة استخراج
> النص وتقدير التوكنز — وهما نفس المكتبات الاختيارية التي يدعمها `PF.py`
> أصلاً (soft dependencies)، فلن يتأثر شيء إن فشل تثبيت أحدهما.

## 2) التشغيل

```bash
python server.py
```

ثم افتح المتصفح على:

```
http://localhost:8000
```

كل شيء — رفع الملفات، الطابور، الـ logs الحية، حالة المفاتيح، مراحل
المعالجة — يعمل من نفس هذه الصفحة. لا حاجة للرجوع لأي طرفية أو تشغيل
`PF.py` يدوياً بشكل منفصل؛ `server.py` يستدعيه داخلياً.

عند أول تشغيل، سيقوم النظام تلقائياً باختبار كل الـ 26 مفتاح API (نفس
سلوك `PF.py` الافتراضي عند تشغيله من CLI بدون `--skip-api-test`) لعرض
حالتها الحقيقية في الواجهة. إن كنت تريد تخطي هذا الاختبار أثناء التطوير:

```bash
ASOST_SKIP_KEY_TEST=1 python server.py
```

## 3) ما الذي يظهر في الواجهة، وهل هو حقيقي؟

**نعم — كل رقم ومؤشر في هذه النسخة حقيقي، مصدره إما محرك الترجمة مباشرة أو
قاعدة بيانات صغيرة خاصة بالداشبورد (`dashboard_jobs.db`) تُنشأ تلقائياً.**
النسخة الأصلية التي أرسلتها كانت تعرض بيانات عشوائية بالكامل (`Math.random`)
في كل مكان تقريباً — تم استبدال ذلك كله:

| العنصر في الواجهة | مصدر البيانات الحقيقي |
|---|---|
| زر رفع الملفات | يرفع الملف فعلياً إلى السيرفر، ويتحقق منه بنفس دالة `validate_input_paths` الأصلية من `PF.py` |
| الطابور (Queue) | مهام حقيقية قيد المعالجة أو منتظرة، بالتتابع تماماً كما صُمم المحرك |
| شريط التقدّم لكل مرحلة | مبني على `system.translation_stats` الحيّة + رسائل السجل الفعلية لكل Phase (1 إلى 5) |
| اللوغ الحي (Terminal) | نفس سجلات `PF.py` (logger 'main' و 'quality_control') مباشرة، بدون توليد نصوص وهمية |
| مخطط TPM | استهلاك التوكنز الفعلي لكل مفتاح من `TokenRateLimiter.get_status()` |
| جدول مفاتيح API | حالة كل مفتاح الحقيقية (نشط/محظور/قريب من الحد)، **للعرض فقط دون أي تعديل** |
| مخطط "الفصول المتتالية" (بديل الـ Gantt) | الفصول تُترجم فعلياً بالتتابع لا بالتوازي — هذا المخطط يعرض التسلسل الحقيقي بدل الإيحاء بعمّال متوازين وهميين |
| خريطة الشبكة (Topology) | حالة حقيقية للمحرك/الطابور/المفاتيح المُشتقة من نفس البيانات أعلاه |
| عدّاد الكتب/الصفحات المُترجمة | من `dashboard_jobs.db` — يبدأ من صفر في أول تشغيل (هذا طبيعي وصحيح، وليس خطأ) |
| CPU / RAM | قراءة حقيقية من `psutil` |

## 4) نقاط مهمة قصدتها بالتصميم

- **نظام مفاتيح الـ API لم يُمسّ إطلاقاً.** المصفوفة داخل
  `EnhancedGeminiAPI.__init__` في `PF.py` هي المصدر الوحيد للمفاتيح، تماماً
  كما كانت. جدول "API Keys" في الواجهة **للمراقبة فقط** — لا يوجد زر
  إضافة/حذف/تدوير مفاتيح من الواجهة عمداً، احتراماً لطلبك ببقاء هذا النظام
  يدوياً بالكامل في الكود.
- **الرفع مقصور على PDF فقط.** لأن `PF.py` نفسه (عبر `validate_input_paths`
  و `extract_pdf_with_precision`) لا يدعم فعلياً سوى ملفات PDF كمدخل (الإخراج
  دائماً DOCX). النسخة القديمة من الواجهة كانت "تسمح" ظاهرياً برفع DOCX لكنها
  كانت ستفشل عليه لاحقاً — تم تصحيح ذلك ليطابق قدرة المحرك الحقيقية.
  "الإيقاف المؤقت" (Pause) يعمل فقط على الملفات التي لم تبدأ معالجتها بعد
  (لأن محرك الترجمة نفسه لا يدعم تجميد عملية جارية في منتصفها) — أما الملف
  الجاري ترجمته فزر "Cancel" عليه يُلغيه فعلياً (عبر إلغاء الـ task) لا
  يوقفه مؤقتاً فقط.
- **المعالجة تسلسلية (ملف واحد في كل مرة)**، بنفس تصميم `PF.py` الأصلي —
  الطابور يعالج الملفات التالية تلقائياً بعد انتهاء كل ملف.
- الاستطلاع (polling) من الواجهة كل 2 ثانية للحالة العامة، وكل 1.2 ثانية
  للّوغ — لا حاجة لإعادة تحميل الصفحة.

## 5) استكشاف الأخطاء

- **"تعذّر الاتصال بالسيرفر الخلفي"** في الواجهة: تأكد أن `python server.py`
  ما زال يعمل في الطرفية ولم يتوقف بخطأ.
- **كل المفاتيح تفشل بخطأ شبكة/403 عند الترجمة**: تأكد أن جهازك يستطيع
  الوصول فعلياً إلى `generativelanguage.googleapis.com` (بعض بيئات
  الاستضافة/الحاويات تحجب الوصول الخارجي افتراضياً — يلزم فتحه من إعدادات
  الشبكة الخاصة بالبيئة التي تُشغّل عليها السيرفر).
- ملفات قواعد البيانات (`dashboard_jobs.db`, `key_statistics.db`,
  `master_translation_enhanced.db`) ومجلد `translation_logs/` تُنشأ تلقائياً
  عند أول تشغيل بجانب `server.py` — احذفها إن أردت البدء من صفر نظيف.
